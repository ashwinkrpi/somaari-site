# Somaari.in UI review: merged plan (for somaari-build-guru)

Merged from the ChatGPT, Claude and Gemini reviews of 23 Nov 2026, rewritten in somaari-build-guru's plan format. Each task is a tagged checklist item (`[simple]` Haiku, `[moderate]` Sonnet, `[complex]` Opus, `[manual]` you). Priority is shown by the stage heading. Source reviewers are in the task text as `(C)`, `(Cl)`, `(G)`.

## How to run

1. Copy this file into the repo as `somaari-site/UI-REVIEW.md`. Use a new name, not `PLAN.md`: the branch is named after the plan file, and `PLAN.md` already holds the finished site-improvements run on `build-guru/PLAN`.
2. `somaari-site/build-guru.toml` already exists (test: `npm run check`, lint: `npm run build`, cost cap $5). Commit the plan on `main` first. The tree must be clean (`dist/` and `dist-baseline/` are already ignored).
3. `cd somaari-site && build-guru run UI-REVIEW.md --dry-run`, then `build-guru run UI-REVIEW.md --yes`.
4. Review branch `build-guru/UI-REVIEW`, then merge it yourself. build-guru never merges or pushes.
5. Do Stage 1 first, look at the result in a browser, then decide whether to run the rest (`--only`, `--from N`, `--max-tasks N` help). `[manual]` tasks are skipped and listed at the end.

Stage order is priority order: High, Medium, Low, Good-to-have.

## Rules every task must follow

Each task runs in a fresh session that reads only its own line, so the rules are repeated in short form in each task. Common ground: plain HTML/CSS/JS, no framework; keep the colour scheme, the minimalist look, dark/light and seasonal themes; keep the hero headline "Routine tasks, minimum effort."; do not remove any section, project or destination unless the task says so; stay usable on phones (breakpoints 40rem and 48rem). `npm run check` and `npm run build` must pass.

## Where things live in somaari-site (so tasks do not need to search)

- `index.html` holds the page. The app cards are NOT hand-written: they are generated by `scripts/build.mjs` into the `<!-- APPS:live -->` and `<!-- APPS:dev -->` markers, from somaari-common's `apps/apps.json`. The Explore tiles are generated by `scripts/explore.mjs` into `<!-- EXPLORE -->`. Edit the generator, not `dist/`.
- Styles: `style.css` (card thumbnail rule is `.card-thumb`), `shared.css`.
- Social images: generated at build time by `scripts/build.mjs` into `dist/og/`.
- Checks: `scripts/check-*.mjs`.

## Conflicts between the reviews and how this plan resolves them

- Screenshot on cards: C wants the screenshot to dominate, Cl and G want the extra Planner screenshot removed. Resolved by one uniform media slot per card (tasks 1 and 2).
- "In development": C keeps the section, Cl merges it into one grid. Resolved by a merged grid with a badge and subdued card (the Stage 2 grid task).
- Link duplication: G removes the "Details" footer link, C wants an "Explore application" button. Resolved by title link plus one primary button (task 3).
- Navigation duplication: G dedupes, C says do not remove destinations. Resolved by removing only repeats and keeping everything reachable.

## Preserve (all reviews agree)

Minimalist plain-HTML look, the colour scheme, dark/light and seasonal themes, separate docs and book sites, blog integration, per-app GitHub links, privacy messaging, the header/footer/"Free book" pill, the games disclaimer. Colour contrast, empty alt text on demo images (the Play buttons carry labels) and the page weight (~350 KB) were checked and need no change.

## Non-goals

No redesign, no new colour scheme, no animations or gradients, no framework, no extra navigation levels, no removal of sections or projects, no change made only for visual novelty.
